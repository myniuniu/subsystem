## 简介
学习进度服务（`learningProgressService`）是系统中用于跟踪和管理用户学习行为的核心模块。该服务通过本地存储机制持久化用户的各项学习数据，包括学习时长、课程完成状态、学习目标达成情况等，并为前端组件提供统一的数据访问接口。服务采用单例模式设计，确保全局数据一致性。

本服务主要支撑 `LearningProgress.jsx` 和 `MyProgress.jsx` 两个核心组件的数据显示需求，同时其数据也可被 `LearningAnalyticsCenter.jsx` 用于更深入的学习行为分析。服务提供了完整的CRUD操作、数据导入导出功能以及防错处理机制，构成了学习追踪系统的数据基石。

## 核心功能与方法
学习进度服务提供了一系列方法来记录、查询和更新用户的学习进度。

### 记录学习时长
`addStudyRecord(subjectId, studyTime, completedLessons = 0)` 方法用于记录一次学习活动。它接收三个参数：学科ID、学习时长（小时）和完成的课时数。
- **功能**：该方法会更新指定学科的总学习时间和完成课时数，累加到总学习时长，并在当日的学习记录中增加相应的时长和任务数。
- **副作用**：自动创建或更新当天的 `dailyRecords` 条目，并向 `activities` 活动列表中添加一条新的学习日志。
- **返回值**：返回更新后的完整数据对象。

```js
// 示例：记录2小时数学学习，完成3个课时
learningProgressService.addStudyRecord('math', 2, 3);
```

### 更新章节完成状态
虽然没有独立的“更新章节”方法，但此功能已集成在 `addStudyRecord` 中。通过传递 `completedLessons` 参数，可以精确地更新特定学科的已完成课时数。服务内部会根据学科ID查找对应条目并进行累加。

### 获取用户进度汇总
服务提供了多个专用方法来获取不同维度的进度汇总：

- `getStudySummary()`：获取一个包含总学习时长、已完成课时、周目标进度、活跃目标数等关键指标的摘要对象。
- `getSubjectProgress()`：获取所有学科的详细进度，包括每个学科的完成百分比和时间进度百分比。
- `getWeeklyStats()`：计算本周的学习统计数据，如总时长、目标完成度、平均每日学习时长等。
- `getAchievements()`：获取成就统计，包括完成的科目数、平均进度和总学习时长。
- `getRecentActivities(limit = 5)`：获取最近的活动记录，按时间倒序排列。

这些方法均基于 `getAllData()` 获取的完整数据集进行计算，确保了数据的一致性和实时性。

## 数据模型定义
学习进度服务维护一个结构化的JSON数据模型，存储于浏览器的 `localStorage` 中，键名为 `learning_progress_data`。

### 核心字段含义
```json
{
  "totalStudyTime": 0,
  "weeklyGoal": 40,
  "subjects": [...],
  "dailyRecords": [],
  "studyGoals": [...],
  "achievements": {...},
  "activities": []
}
```
- **totalStudyTime**: 用户自注册以来的累计学习总时长（小时）。
- **weeklyGoal**: 用户设定的每周学习目标时长（小时），默认为40小时。
- **subjects**: 学科数组，每个学科对象包含ID、名称、图标、总学习时长、目标时长、已完成课时、总课时、最后学习日期和难度等级。
- **dailyRecords**: 每日学习记录数组，每条记录包含日期、当日学习时长和完成的任务数。
- **studyGoals**: 学习目标数组，每个目标包含ID、标题、描述、当前进度、目标值、截止日期、优先级和完成状态。
- **achievements**: 成就对象，记录证书总数、完成课程数、学习连续天数和项目总数。
- **activities**: 活动日志数组，记录用户的所有学习相关活动。

### 时间戳处理规则
- **日期格式**：所有日期字符串均采用ISO 8601标准的 `YYYY-MM-DD` 格式（例如：`2024-01-15`）。这是通过 `new Date().toISOString().split('T')[0]` 生成的。
- **时间戳**：活动记录中的 `timestamp` 字段使用完整的ISO 8601时间戳（`YYYY-MM-DDTHH:mm:ss.sssZ`），由 `new Date().toISOString()` 生成。
- **辅助方法**：
  - `getDateAfterDays(days)`: 返回从今天起指定天数后的日期（`YYYY-MM-DD` 格式）。
  - `getDaysUntil(dateStr)`: 计算给定日期距离今天的天数差。

### 同步机制
由于数据存储在客户端的 `localStorage` 中，因此不存在跨设备同步机制。这意味着：
- **优点**：读写速度快，无需网络请求，离线可用。
- **缺点**：数据仅限于当前设备和浏览器。如果用户更换设备或清除浏览器缓存，数据将丢失。
- **数据保护**：提供了 `exportData()` 和 `importData(jsonData)` 方法，允许用户手动导出JSON备份并在需要时重新导入，作为数据迁移和恢复的解决方案。

## 组件集成与数据流
学习进度服务是连接后端数据与前端UI的关键桥梁，其数据被多个组件消费。

### 支撑 LearningProgress.jsx
`LearningProgress.jsx` 是学习进度服务最主要的消费者。它在组件挂载时调用 `loadData` 函数，通过服务实例获取各类数据：
```js
const loadData = async () => {
  const summary = learningProgressService.getStudySummary();
  const subjects = learningProgressService.getSubjectProgress();
  // ... 其他数据获取
};
```
这些数据随后被用于渲染统计卡片、学科进度条、学习趋势图和目标列表。当用户在界面中添加新目标时，会调用 `learningProgressService.addStudyGoal(...)`，触发数据更新和视图刷新。

### 支撑 MyProgress.jsx
`MyProgress.jsx` 组件展示用户的个人总体进度。虽然其数据源可能来自其他服务，但其设计理念与 `learningProgressService` 高度一致，都关注于量化学习成果（如完成率、技能积分、学习时长）。这表明 `learningProgressService` 的数据模型可以作为 `MyProgress` 数据的底层来源之一。

### 与 LearningAnalyticsCenter.jsx 整合
`LearningAnalyticsCenter.jsx` 是一个高级数据分析中心。虽然其直接数据源可能是更复杂的后端API，但 `learningProgressService` 可以作为其数据整合的一个重要组成部分。例如，`learningProgressService` 提供的学科掌握率、学习时长分布等数据，可以被 `LearningAnalyticsCenter` 聚合，用于生成更全面的学情报告和个性化建议。

## 批量更新与优化策略
尽管 `learningProgressService` 当前未提供显式的批量更新API，但可以通过以下方案实现优化：

### 批量更新进度的优化方案示例
一种高效的批量更新方案是引入一个 `batchUpdate(records)` 方法。该方法接收一个学习记录数组，在单次事务中处理所有更新，最后只保存一次数据，避免了多次I/O操作。

```js
// 伪代码示例
batchUpdate(records) {
  const data = this.getAllData();
  records.forEach(record => {
    // 在内存中处理所有更新逻辑
    this.updateSingleRecord(data, record);
  });
  this.saveData(data); // 仅执行一次持久化
}
```

### 防抖处理
对于频繁触发的操作（如实时计时器每分钟更新一次），应实施防抖（Debounce）策略。例如，可以设置一个定时器，只有当用户停止操作（如离开页面）或达到一定时间间隔（如5分钟）后，才将累积的更新写入存储。这能显著减少对 `localStorage` 的写入次数，提升性能。

### 离线缓存策略
当前服务已经实现了基本的离线缓存，因为 `localStorage` 本身就是一种客户端缓存。为了增强健壮性，可以：
1.  **错误处理**：在 `saveData` 方法中捕获异常，当存储空间不足时，提示用户导出数据。
2.  **内存缓存**：在服务内部维护一个内存中的数据副本，所有读取操作优先从此副本获取，仅在初始化和保存时与 `localStorage` 交互，进一步减少I/O开销。
3.  **数据压缩**：对于大型数据集，可以在存储前进行简单的压缩（如移除不必要的空格），但这在当前数据规模下收益不大。

## 典型使用场景
- **日常学习打卡**：用户完成一节课程后，调用 `addStudyRecord` 记录学习时长和完成的课时。
- **目标管理**：用户设定一个“一周内完成10小时编程学习”的目标，通过 `addStudyGoal` 创建，系统会自动跟踪进度并在 `LearningProgress` 界面显示。
- **数据迁移**：用户更换电脑时，先在旧设备上使用 `exportData` 导出JSON文件，然后在新设备的 `LearningProgress` 界面通过导入功能恢复所有历史数据。
- **周报生成**：在每周结束时，管理员或用户可以查看 `getWeeklyStats` 的结果，了解本周学习目标的完成情况。

## 边界情况处理指南
- **无效的学科ID**：当调用 `addStudyRecord` 传入一个不存在的 `subjectId` 时，服务会忽略对该学科的更新，但仍会更新 `totalStudyTime` 和 `dailyRecords`。
- **超出目标的进度**：`updateGoalProgress` 方法使用 `Math.min(progress, goal.target)` 确保进度不会超过目标值。
- **过期的目标**：`getStudyGoals` 方法会计算 `isOverdue` 字段，帮助UI正确标记已过期的目标。
- **存储读取失败**：`getStoredData` 方法包含 `try-catch` 块，若读取失败则返回 `null`，触发 `initializeData` 创建初始数据，保证服务始终有可用数据。
- **数据导入失败**：`importData` 方法捕获解析错误，返回 `{ success: false }` 对象，前端可根据此结果给出用户友好的错误提示。
